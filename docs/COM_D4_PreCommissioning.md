# تحویلی D4 — پیش‌راه‌اندازی و آزمون سرد (A-Check)

ماژول COM / MOD-13 · زیرماژول ۱۳٫۲ · دامنهٔ `d15`

---

## ۰. چکیده

بستهٔ آزمون (`CheckRecordPack`) ظرف برگه‌های آزمون یک سیستم است؛ هر برگه
(`CheckSheet`) از ردیف‌های پارامتری (`CheckSheetLine`) ساخته می‌شود و نتیجه‌اش
**از ردیف‌ها مشتق می‌شود، نه انتخاب دستی کاربر**. وقتی همهٔ بسته‌های نوع «الف»
یک سیستم تأیید شدند و عدم انطباق بازی نماند، دروازهٔ آزمون سرد آن سیستم باز
می‌شود و مسیر MC در D6 آزاد می‌گردد.

| سنجه | مقدار |
|---|---|
| جدول جدید | ۳ (مجموع ۸۳) |
| مهاجرت | `0014 check_records` — ۱۰ گزاره، فقط CREATE |
| مجوز جدید | ۲ (مجموع ۸۸) |
| اندپوینت جدید | ۹ (مجموع cnt+com: ۴۳) |
| صادرات موتور COM | ۴۷ |
| آزمون D4 | ۴۰ موتور + ۳۳ REST |
| کل آزمون پروژه | ۱۴۲۷ سبز |

## ۱. مدل داده

### ۱٫۱ `CheckRecordPack` — بستهٔ آزمون

| ستون | نوع | توضیح |
|---|---|---|
| `Id` | uuid | کلید |
| `ProjectId` | text! | دامنهٔ پروژه |
| `SystemId` | text! | سیستم موضوع آزمون |
| `PackNo` | text! | شمارهٔ بسته — یکتا در پروژه |
| `TitleFa` | text! | عنوان |
| `PackType` | text! | `a` آزمون سرد · `b` آزمون گرم |
| `DisciplineCode` | text | رشته |
| `TotalSheets` / `ClearedSheets` | int | شمارندهٔ مشتق |
| `ClearedAt` / `ClearedBy` | date/text | مهر تأیید |
| `Status` | text! | `draft` · `in_progress` · `cleared` · `rejected` |

یکتایی: `(ProjectId, PackNo)`

### ۱٫۲ `CheckSheet` — برگهٔ آزمون

| ستون | نوع | توضیح |
|---|---|---|
| `PackId` | text! | بستهٔ مادر |
| `SheetNo` | text! | یکتا در پروژه |
| `SheetType` | text! | `a`/`b` — **از بسته ارث می‌برد، کاربر نمی‌فرستد** |
| `TestKind` | text! | نوع آزمون؛ باید با `SheetType` سازگار باشد |
| `TestDate` / `TestedBy` / `WitnessedBy` | | امضا و شهادت |
| `ResultFa` | text | `pass` · `fail` · `conditional` — **مشتق از ردیف‌ها** |
| `NcrRef` | text | ارجاع عدم انطباق در صورت مردودی |
| `Status` | text! | `draft` · `signed` · `void` |

### ۱٫۳ `CheckSheetLine` — ردیف پارامتر

| ستون | نوع | توضیح |
|---|---|---|
| `SheetId` / `LineNo` | text!/int! | یکتا با هم |
| `ParameterFa` | text! | نام پارامتر |
| `ExpectedValue` / `ActualValue` / `UnitFa` | text | طراحی در برابر واقعی |
| `IsMandatory` | bool! (پیش‌فرض ۱) | ردیف اختیاری بر نتیجه اثر ندارد |
| `Passed` | bool (nullable) | `null` = هنوز سنجیده نشده |

> `Passed` عمداً سه‌حالته است. اگر بولی دوحالته بود، «هنوز نسنجیده‌ایم» با
> «مردود شد» یکی می‌شد و برگه‌های ناتمام مردود جلوه می‌کردند.

## ۲. تصمیم‌های موتور

### ۲٫۱ تفکیک آزمون سرد و گرم

`TEST_KINDS_BY_TYPE` با **همپوشانی صفر** (آزمون‌شده):

| نوع | آزمون‌ها |
|---|---|
| **الف (سرد)** | هیدرواستاتیک · شست‌وشو · دمش هوا · مقاومت عایقی · کنترل حلقه · کالیبراسیون · هم‌محوری |
| **ب (گرم)** | بی‌بار · زیر بار · ارتعاش · عملکرد · اینترلاک |

ثبت آزمون گرم در بستهٔ سرد (و برعکس) با `E-COM-KIND-PACK-MISMATCH` رد می‌شود.
این قاعده همان چیزی است که مانع می‌شود تیم اجرا با نام‌گذاری خلاقانه، آزمون زیر
بار را پیش از تکمیل مکانیکی انجام دهد.

### ۲٫۲ نتیجه از ردیف مشتق می‌شود — `sheetVerdict`

| وضعیت ردیف‌ها | نتیجه |
|---|---|
| حداقل یک ردیف الزامیِ مردود | `fail` |
| ردیف الزامی سنجیده‌نشده | `pending` |
| همهٔ الزامی‌ها قبول | `pass` |
| هیچ ردیف الزامی وجود ندارد | `pending` |

دو قاعدهٔ عمدی: **`fail` بر `pending` اولویت دارد** (یک مردودی قطعی، ابهام بقیه
را بی‌اثر می‌کند) و **سکوت قبولی نیست** — ردیف بی‌قرائت جلوی امضا را می‌گیرد.
`IsMandatory` تعیین‌نشده الزامی فرض می‌شود؛ سهو در ورود داده نباید پارامتر را از
دایرهٔ سنجش خارج کند.

### ۲٫۳ امضا — `canSignSheet`

- **برگهٔ مردود هم امضا می‌شود.** امضا ثبت واقعیت است نه اعلام قبولی؛ نتیجهٔ
  مردود باید سند رسمی داشته باشد تا NCR به آن ارجاع دهد.
- بدون شاهد → `E-COM-NO-WITNESS`. آزمون بدون شاهدِ ثبت‌شده سند نیست.
- ردیف ناتمام → `E-COM-SHEET-PENDING`.
- برگهٔ امضاشده قفل است؛ ویرایش قرائت → `E-COM-SHEET-LOCKED`.

### ۲٫۴ پیشرفت بسته — `packProgress`

مبنا برگه‌های **امضاشده**؛ برگهٔ `void` از مخرج حذف می‌شود — اگر شمرده می‌شد،
تیم برای حفظ درصد، برگهٔ اشتباه را باطل نمی‌کرد. نتیجهٔ `conditional` مانع تأیید
بسته نیست؛ تصمیم‌گیری دربارهٔ شرط به دروازهٔ MC واگذار می‌شود.

### ۲٫۵ دروازهٔ آزمون سرد — `coldTestClearance`

طبق ADR-COM-03 **همهٔ موانع یک‌جا** برگردانده می‌شوند، نه اولین مانع:

| شرط | اثر |
|---|---|
| هیچ بستهٔ نوع الف وجود ندارد | مانع |
| بستهٔ الف تأییدنشده | مانع |
| عدم انطباق باز در دامنهٔ سیستم | **مانع سخت** |
| پیشرفت فیزیکی < ۱۰۰٪ | **هشدار، نه مانع** |

بسته‌های نوع «ب» در این دروازه شمرده نمی‌شوند. پیشرفت فیزیکی عمداً هشدار است:
کارهای جزئی ساخت معمولاً تا پس از آزمون سرد ادامه دارند و مانع کردنش دروازه را
غیرقابل عبور می‌کند.

**پل عدم انطباق:** جدول `Ncr` ستون سیستم ندارد. اتصال از راه
`SystemBoundaryMapping` با `TargetKind='activity'` به `Ncr.ActivityId` زده شده
است — بدون افزودن ستون به جدول ماژول کیفیت (قید ارتقای درون‌برنامه‌ای).

## ۵. دسترسی

| مجوز | طبقه‌بندی | دارندگان |
|---|---|---|
| `com.checksheet.record` | internal | مدیر راه‌اندازی · بازرس کیفی · سرپرست کارگاه |
| `com.checksheet.sign` | internal | مدیر راه‌اندازی · بازرس کیفی |

**تفکیک وظیفه:** سرپرست کارگاه قرائت ثبت می‌کند اما امضا نمی‌کند — ثبت‌کننده و
تأییدکنندهٔ نتیجه یک نفر نیستند. این تفکیک با **خودِ مجوز** اعمال می‌شود، نه با
بالا بردن طبقه‌بندی؛ طبقه‌بندی باید با سطح دسترسی نقشِ مجری بخواند وگرنه بازرس
کیفی (سطح internal) با `DENY_CLEARANCE` بیرون می‌ماند.

راستی‌آزمایی زنده: `u-qc` امضا ✅ · `u-site` ثبت ✅ / امضا ⛔۴۰۳ · `u-client` ⛔۴۰۳.

## ۷. راستی‌آزمایی زنده

سناریوی کامل روی پورت ۴۷۹۹ اجرا شد:

1. ساخت سیستم U-500 → بستهٔ سرد TP-101 ✅
2. آزمون گرم در بستهٔ سرد → ⛔ `E-COM-KIND-PACK-MISMATCH`
3. برگهٔ هیدروتست، ۳ ردیف (۲ الزامی) → نتیجه «در انتظار»
4. امضای برگهٔ ناتمام → ⛔ `E-COM-SHEET-PENDING`
5. دو قرائت توسط سرپرست کارگاه → نتیجه «قبول»
6. امضای سرپرست کارگاه → ⛔ HTTP 403
7. امضای بازرس کیفی → ✅
8. تأیید بسته → ✅ ۱/۱ · دروازهٔ سرد ✅ باز
9. ثبت NCR باز روی فعالیت مرزبندی‌شده → دروازه ⛔ بسته با مانع صریح
10. NCR بسته روی سیستم دیگر → دروازه ✅ باز (فیلتر وضعیت درست کار می‌کند)

**دو یافتهٔ curl زنده که از آزمون‌ها گریخته بود:**

- پیام `E-COM-KIND-PACK-MISMATCH` عبارت «آزمون آزمون زیر بار» تولید می‌کرد
  (تکرار واژه در درون‌یابی). اصلاح شد.
- `preCommSummary.byType` وقتی بستهٔ گرمی نبود کلید `b` را حذف می‌کرد و
  مصرف‌کننده با `KeyError` می‌شکست. حالا هر دو کلید همیشه هستند؛ دو ادعای آزمون
  این را قفل کرد.
