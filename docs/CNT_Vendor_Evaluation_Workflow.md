# ارزیابی دوره‌ای و بهبود طرف قرارداد — d14-p8

## محدوده و دادهٔ واقعی

- `d14-p8-s1`: ثبت امتیاز شش محور، مشاهدهٔ ارزیابی‌ها، تأیید/رد مستقل و اصلاح ارزیابی ردشده.
- `d14-p8-s2`: تاریخچهٔ تأییدشده، روند، پایش C/D و ثبت و پیگیری اقدامات بهبود.
- هر مقصد فقط محتوای خودش را نمایش می‌دهد؛ اسکرول داخلی و بدون اسکرول کل پنل.
- منبع انتخاب طرف قرارداد، `ContractMaster.ContractorName` یا `PurchaseOrder.VendorName` در همان پروژه است؛ پیش‌نویس و لغوشده انتخاب نمی‌شوند. اتصال نرم است و FK فیزیکی بین‌ماژولی وجود ندارد.
- هر ارزیابی متعلق به یک پیمان/سفارش و تاریخ دوره است؛ طرف‌های هم‌نام یا چند پیمان یک طرف به‌اشتباه ادغام نمی‌شوند. این نما دفتر مستقل اشخاص/تأمین‌کنندگان ایجاد نمی‌کند.
- دادهٔ نمونهٔ `PARTY_SEED` حذف شده است. نبود سابقه، پیام خالی و «—» دارد؛ فقدان سابقه امتیاز صفر تلقی نمی‌شود.

## محاسبه و تاریخچه

فرمول فعلی `vendorRating.rateParty` حفظ شده: ایمنی/کیفیت/زمان هرکدام ۲۰، قیمت/مستندات هرکدام ۱۵ و همکاری ۱۰. هر شش ورودی عددی ۰ تا ۱۰۰ الزامی‌اند. رتبه‌بندی روی میانگین وزنی پیش از گرد کردن انجام می‌شود؛ A≥85، B≥70، C≥55 و D کمتر از 55.

امتیاز، رتبه، ضعیف‌ترین محور و مشخصات طرف از سمت سرور تولید می‌شوند و قابل جعل با ورودی نیستند. تاریخ دوره معتبر و غیرآینده و مرجع سند الزامی است. یک رکورد برای هر پروژه/نوع منبع/شناسه منبع/تاریخ دوره مجاز است.

تنها دوره‌های `approved` وارد روند می‌شوند. مقایسه با دورهٔ تأییدشدهٔ قبلیِ همان منبع بر اساس تاریخ، نه ترتیب ثبت است. اولین دوره روند «—» دارد. خلاصهٔ میانگین، توزیع رتبه و فهرست پایش فقط آخرین ارزیابی تأییدشدهٔ هر منبع را می‌شمارد؛ تاریخچهٔ کامل جدا نمایش داده می‌شود. از مبالغ چندارزی، «ارزش در معرض ریسک» ساختگی تولید نمی‌شود.

## گردش و کنترل دسترسی

- `cnt.rating.view`: خواندن فضای پروژه؛ مطابق دسترسی قبلی مشاهدهٔ پیمان.
- `cnt.rating.edit`: مدیر پیمان؛ ثبت ارزیابی و اقدامات و ثبت اجرای آن‌ها.
- `cnt.rating.approve`: مدیر پروژه و کارفرما؛ تصمیم مستقل و تأیید اثربخشی.
- ارزیابی: `submitted → approved/rejected`. ثبت‌کننده اجازهٔ تصمیم روی ارزیابی خودش ندارد. شرح تصمیم الزامی است.
- ارزیابی ردشده فقط توسط ثبت‌کننده قابل اصلاح امتیاز/سند و ارسال مجدد است. منبع و دوره تغییر نمی‌کنند. سابقهٔ تصمیم قبلی و نسخه‌های اصلاحی در AuditLog حفظ می‌شود.
- اقدام: `open → in_progress → completed → verified`؛ انجام نیازمند مستند است و تأییدکننده نمی‌تواند همان ثبت‌کنندهٔ انجام باشد. بررسی‌کننده می‌تواند `completed → in_progress` را با علت بازگشایی کند. لغو با دلیل از open/in_progress مجاز است.
- مسئول باید کاربر فعال دارای دسترسی مشاهده به همین پروژه باشد. ثبت انجام به نمایندگی مسئول توسط نقش دارای مجوز ویرایش انجام می‌شود؛ تعیین مسئول، مجوز جدید اعطا نمی‌کند.
- موعد قبل از تاریخ ارزیابی پذیرفته نیست؛ اقدامات بازِ سررسیدگذشته مشخص می‌شوند.
- تمام تغییرات تراکنشی همراه AuditLog، کنترل RowVersion و اعتبارسنجی پروژه/فیلدهای مجاز انجام می‌شوند. REST عمومی حق تغییر دو جدول اختصاصی را ندارد.
- هیچ اثری بر مبلغ پیمان، صورت‌وضعیت یا نرخ‌ها ندارد؛ پیش‌بینی یا توصیهٔ AI تولید نمی‌شود.

## ماندگاری و API

جدول‌ها: `VendorEvaluation` و `VendorImprovement`؛ تعریف در persistence، مهاجرت ثبت‌شدهٔ 0076 و اسکریپت افزایشی MSSQL در `db/mssql/V006__vendor_evaluation_and_improvement.sql`.

- `GET /api/cnt-rating/:projectId`
- `POST /api/cnt-rating/:projectId/evaluations`
- `POST /api/cnt-rating/:projectId/evaluations/:id/decision`
- `POST /api/cnt-rating/:projectId/evaluations/:id/resubmit`
- `POST /api/cnt-rating/:projectId/actions`
- `POST /api/cnt-rating/:projectId/actions/:id/transitions`

سقف هر مجموعه ۲۰۰۰ رکورد است؛ بیش از سقف خطای صریح می‌دهد، نه گزارش ناقص. تاریخ در ذخیره‌سازی ISO و ورودی فارسی شمسی است.

## اعتبارسنجی این مرحله

```sh
npm run build:vendorrating --silent
npm run build:sql --silent
npm run build:rbac --silent
npx tsc --noEmit
node --test server/vendorRating.unit.test.mjs server/vendorRating.rest.test.mjs \
  server/contractVariation.unit.test.mjs server/contractVariation.rest.test.mjs \
  server/contractAmendment.unit.test.mjs server/contractAmendment.rest.test.mjs \
  server/cnt.forms.test.mjs server/cntipc.workspace.rest.test.mjs
```

۱۲۲ تست متمرکز موفق؛ مرورگر با پایگاه موقت: ارزیابی→تأیید مستقل→روند→اقدام→انجام→تأیید اثربخشی، اصلاح/ارسال مجدد ارزیابی ردشده، دسترسی فقط‌خواندنی برنامه‌ریز و جداسازی نماها. ابعاد ۱۴۴۰×۹۰۰ و ۱۲۸۰×۸۰۰ بدون اسکرول بیرونی بررسی شد. رگرسیون مقصدهای پیمان و قالب صورت‌وضعیت نیز بررسی شد.

SQL Server در این محیط در دسترس نیست؛ اسکریپت مهاجرت آماده است ولی روی SQL اجرا نشده. آزمون ماندگاری با درایور JSON و پوشه‌های موقت انجام شده و دادهٔ کسب‌وکار کاربر تغییر نکرده است.
