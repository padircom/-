# مرکز گزارش‌ساز A4 سه‌لوگو — معماری (rpt-v1)

نسخه ۱.۰ · ۲۰۲۶-۰۹-۰۸ · وضعیت: پیاده‌سازی‌شده و تست‌شده (۴۲ تست)

## ۱. هدف

یک موتور گزارش‌سازی مشترک برای همهٔ ماژول‌های Arena Platform که خروجی چاپی استاندارد A4
با سربرگ سه‌لوگو (پیمانکار / کارفرما / مشاور) تولید می‌کند و شکاف‌های زیر را می‌بندد:

| شکاف | ماژول | شرح |
|---|---|---|
| PEX-G3 | کنترل پروژه | نبود خروجی Excel/Word/PDF |
| HRM-H06 | منابع انسانی | نبود گزارش رسمی نیروی انسانی |
| CKM-C01 | ارتباطات و دانش | نبود موتور خروجی برای نامه و صورت‌جلسه |

## ۲. قید بنیادی: بدون وابستگی npm

هیچ کتابخانهٔ PDF/Excel اضافه نشد. مسیرها:

| قالب | روش | دلیل |
|---|---|---|
| PDF | HTML + `@page` + `window.print()` | موتور چاپ مرورگر خودش A4 و صفحه‌بندی را می‌فهمد؛ فونت فارسی و RTL بدون درگیری با subset فونت |
| Word | HTML با `xmlns:w="urn:schemas-microsoft-com:office:word"` و پسوند `.doc` | Word این قالب را بومی باز می‌کند |
| Excel | جدول HTML با `xmlns:x="urn:schemas-microsoft-com:office:excel"` و پسوند `.xls` | Excel جدول را به شبکهٔ سلولی تبدیل می‌کند |
| CSV | RFC 4180 با `\r\n` و BOM هنگام دانلود | بدون BOM، Excel فارسی را به‌هم‌ریخته می‌خواند |

## ۳. تصمیم‌های معماری

- **ADR-R1 — سرویس خالص، کامپوننت ناخالص.** `src/services/reporting.ts` هیچ ارجاعی به
  `window`، `Blob` یا `document` ندارد، پس مستقیم در Node تست می‌شود. helperهای
  `download()` و `printHtml()` داخل `ReportCenter.tsx` ماندند.
- **ADR-R2 — دو قالب، یک تعریف.** `Audience = "internal" | "official"`؛ همان `ReportDef`
  با دو پوستهٔ متفاوت رندر می‌شود. رسمی: سه لوگو + شماره سند + نسخه + فهرست توزیع + جدول امضا.
  داخلی: فقط نشان «نسخه کاری» و نام تهیه‌کننده.
- **ADR-R3 — رنگ‌بندی هم‌خوان Primavera P6.** `PRIMAVERA_COLORS` با شش وضعیت؛
  `statusFromFloat(tf, progress)` وضعیت را از شناوری کل استخراج می‌کند
  (پیشرفت ۱۰۰٪ → تکمیل‌شده؛ TF ≤ ۰ → بحرانی؛ TF ≤ ۱۰ → نزدیک بحرانی؛ پیشرفت ۰ → شروع‌نشده).
- **ADR-R4 — هندسهٔ صفحه صریح است.** `A4` = ۲۱۰×۲۹۷ mm با حاشیهٔ بالا ۳۲ (جای سربرگ)،
  پایین ۱۸ (جای پاصفحه) و کناره ۱۵. `rowsPerPage()` و `paginate()` تعداد صفحه را
  پیش از خروجی برآورد می‌کنند تا کاربر غافلگیر نشود.
- **ADR-R5 — دروازهٔ انتشار.** `publishGate()` نسخهٔ **رسمی** را در سه حالت می‌بندد:
  عدم انطباق عمدهٔ باز، دورهٔ تأییدنشده، و نقض مهلت قراردادی (time-bar).
  نسخهٔ داخلی هرگز مسدود نمی‌شود — تحلیل نباید بلوکه شود، فقط ابلاغ.
- **ADR-R6 — اعتبارسنجی سربرگ پیش از خروجی.** هفت خطا (`E-RPT-101..107`) و دو هشدار
  (`W-RPT-301/302`). تا وقتی خطا هست، هر چهار دکمهٔ خروجی غیرفعال‌اند.
- **ADR-R7 — شمارهٔ سند استاندارد.** `documentNumber()` → `OG-2401-RPT-M-0007-R01`.
- **ADR-R8 — فرار دادن اجباری.** هر مقدار متنی از مسیر `escapeHtml()` یا `csvCell()`
  عبور می‌کند؛ نام پروژهٔ حاوی `&` یا `"` نباید سند را بشکند.

## ۵. صادرات کلیدی سرویس

## ۶. رابط کاربری

`src/components/ReportCenter.tsx` در تب «گزارش‌ها»ی میز کار کنترل پروژه
(`PmaWorkspace`، مسیر `d3-p6-14`) سوار شده است. سه ستون:

1. کاتالوگ ۱۴ گزارش — گزارش‌های نامجاز برای قالب فعلی کم‌رنگ می‌شوند.
2. انتخاب قالب داخلی/رسمی + ویرایش زندهٔ سه لوگو، نام سه طرف، شماره سند، نسخه،
   دوره، تهیه‌کننده، تأییدکننده و فهرست توزیع.
3. پیش‌نمای برگهٔ A4 با ابعاد واقعی (مقیاس ۰٫۶۲) + چهار دکمهٔ خروجی + فهرست ایرادها.

هر خروجی در `auditLogger` با رویداد `RPT_EXPORT` ثبت می‌شود.

## ۷. تست

`server/rpt.test.mjs` — ۴۲ تست روی `server/rptLogic.js` (تولیدشده با esbuild از فایل TS،
اسکریپت `build:rpt`). پوشش: هندسهٔ صفحه، صفحه‌بندی، رنگ‌بندی، قالب‌بندی عدد و درصد،
شمارهٔ سند، هر هفت خطای سربرگ، دروازهٔ انتشار، فرار HTML و CSV، حضور سه لوگو،
تفاوت رسمی/داخلی، فضای‌نام Word و Excel، و یکپارچگی کاتالوگ.
