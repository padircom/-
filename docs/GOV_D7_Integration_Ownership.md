# GOV D7 — یکپارچگی، مالکیت داده و آشتی‌دهی

خلاصه ۳ خط: هر عدد یک مالک دارد و فقط ماژول مالک آن را می‌نویسد؛ حاکمیت صرفاً می‌خواند و مهر می‌زند. سلامت هر اتصال از فاصله تا آخرین همگام‌سازی موفق نسبت به `sla_hours` محاسبه می‌شود. اختلاف اعداد بین ماژول‌ها با گزارش آشتی‌دهی آشکار می‌شود، نه با اصلاح خودکار.

## ۱) جدول مالکیت داده (قفل)

| فیلد | مالک |
|---|---|
| `progress`, `baseline` | d2 (PEX) |
| `evm`, `kpi`, `variance` | d3 (PMA) |
| `risk`, `claim` | d4 (RCC) |
| `cost` | d5 |
| `document` | d1 (PIM) |

`canGovWrite(field)` برای هر کلید بالا `false` برمی‌گرداند — تلاش برای نوشتن، خطای سرویس است نه هشدار.

## ۲) سلامت اتصال

```
h = ساعت از آخرین سینک موفق
h ≤ sla → ok | h ≤ 2×sla → warn | else fail
```
`sla_hours` پیش‌فرض ۲۴ و برای هر کانکتور قابل تنظیم است.

## ۳) کانکتورهای پایه

| سامانه | حوزه مالک | جهت | SLA |
|---|---|---|---|
| Primavera P6 | d2 | Pull | ۲۴h |
| ERP / SAP | d5 | Pull | ۲۴h |
| EDMS | d1 | Two-way | ۲۴h |
| Power BI Gateway | d3 | Push | ۲۴h |

## ۴) آشتی‌دهی (Reconciliation)
گزارش دوره‌ای که سه عدد را کنار هم می‌گذارد: پیشرفت d2 · EV در d3 · هزینه واقعی d5. اختلاف بیش از آستانه (پیش‌فرض ۲٪) یک یافته ممیزی `major` تولید می‌کند و به تصمیم مرتبط می‌شود. **هیچ اصلاح خودکاری انجام نمی‌شود.**

## ۵) تست‌های پذیرش (پیاده‌شده)
سینک ۶ ساعت پیش → `ok` · ۳۰ ساعت → `warn` · ۷ روز → `fail` ✔ · `canGovWrite("evm") = false` ✔
