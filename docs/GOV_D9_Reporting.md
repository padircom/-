# GOV D9 — گزارش‌ها، قالب‌ها و خروجی‌ها

خلاصه ۳ خط: هفت گزارش پایه حاکمیتی تعریف می‌شود که همگی از داده مالکِ ماژول مبدأ می‌خوانند و تاریخ داده (DataDate) را قفل می‌کنند. فرمت‌های مجاز d6 همان `pdf/word/excel/json` موجود در `domainExportFormats` است. Excel ظرف است، نه منبع حقیقت.

## ۱) فهرست گزارش‌ها

| کد | عنوان | منبع | مخاطب | تناوب |
|---|---|---|---|---|
| GOV-R01 | وضعیت گردش فرآیندها و نقض SLA | `gov_wf_task` + موتور D3 | PM / PMO | روزانه |
| GOV-R02 | نردبان تشدید باز | `gov_escalation` | PMO | هفتگی |
| GOV-R03 | کارنامه انطباق و یافته‌ها | `gov_audit_finding` | PMO / کیفیت | ماهانه |
| GOV-R04 | وضعیت CAPA و معوقات | `gov_capa` | مالکان اقدام | هفتگی |
| GOV-R05 | ذی‌نفعان و تعهد | `gov_stakeholder` + `gov_engagement` | مدیر پروژه | ماهانه |
| GOV-R06 | سلامت یکپارچگی و آشتی‌دهی | `gov_sync_run` + D7 | فناوری اطلاعات / PMO | روزانه |
| GOV-R07 | دفتر تصمیم و اختیار (یک‌صفحه EXEC) | `gov_decision` + evidence | کمیته راهبری | ماهانه |

## ۲) قواعد ثابت گزارش
1. هر گزارش هدر ثابت دارد: پروژه · DataDate · نسخه فرمول · تولیدکننده.
2. اعداد ارجاعی با پیشوند ماژول مالک نمایش داده می‌شوند (`d3:CPI=0.91`) تا منشأ گم نشود.
3. گزارش با یافته `critical` بازِ بدون CAPA، مهر «مشروط» می‌خورد.
4. خروجی JSON برای BI؛ Excel فقط برای تبادل، بدون بازخوانی به‌عنوان منبع.

## ۳) قالب EXEC (یک صفحه)
نوار بالا: امتیاز انطباق + باند · تعداد نقض SLA · تصمیم‌های باز · سلامت کانکتورها.
بدنه: سه بلوک — تصمیم‌های نیازمند اختیار بالاتر · یافته‌های Critical · گام‌های در تشدید L2/L3.
پانویس: هش آخرین رکورد زنجیره ممیزی (اثبات یکپارچگی گزارش).

## ۴) نگاشت UI
هدر ورک‌اسپیس d6 همان چهار سنجه نوار بالای EXEC را زنده نمایش می‌دهد (انطباق ٪، نقض SLA، تصمیم باز) — گزارش صرفاً همان اعداد را در قالب چاپی می‌ریزد.
