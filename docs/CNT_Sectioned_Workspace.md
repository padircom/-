# نمایش بخش‌محور مدیریت پیمان

به‌جای پرش به نقطه‌ای از یک صفحهٔ بلند، سایدبار فقط بخش منتخب را در پنل اصلی
نمایش می‌دهد. انتخاب‌گر پیمان بالای پنل و خارج از اسکرول محتواست؛ انتخاب پیمان
در میزبان d14 و با دامنهٔ پروژه حفظ می‌شود، حتی هنگام رفت‌وبرگشت به قالب‌های
صورت‌وضعیت، ریسک یا ارزیابی. فرم‌های وابسته به پیمان هنگام تغییر پیمان/بخش
دوباره ساخته می‌شوند تا ورودی پیش‌نویس پیمان قبلی روی پیمان تازه ثبت نشود.

| مقصد | محتوای نمایش‌داده‌شده |
|---|---|
| ثبت شناسنامه و الحاقیه‌ها | خلاصه، ثبت شناسنامه و مدیریت الحاقیه |
| فهرست بها و مراحل مقطوع | جدول ردیف‌ها، مراحل و ثبت ردیف |
| تغییر مقادیر و کار جدید | درخواست‌های مقدار و توافق نرخ |
| ضمانت‌نامه و پایش انقضا | سلامت وثیقه، دفتر و ثبت ضمانت‌نامه |
| پیش‌پرداخت و سپرده | دفتر، ثبت قسط و محاسبهٔ بازیافت موجود |
| شاخص‌ها و هشدارها | سنجه‌ها، عکس دوره‌ای و قواعد هشدار |
| پیشرفت پیمان | پیشرفت، منحنی S، تفکیک و نقاط عطف موجود |
| گزارش‌های پیمان | کاتالوگ و خروجی گزارش‌های موجود |
| برگهٔ ریزمتره | فرم موجود ریزمتره |
| صورت‌وضعیت پیمانکار جزء | دفتر و گردش موجود پیمانکار جزء |
| انطباق با دفتر مالی | تطبیق، حساب مقصد و ارسال/برگشت مالی موجود |

پیشرفت و گزارش‌ها، که پیش‌تر فقط در انتهای صفحهٔ بلند دیده می‌شدند، اکنون
گزینه‌های مستقلی زیر فرایند شاخص و انطباق دارند. جایگاه اصلی فرایندهای مالی،
قالب‌های صورت‌وضعیت و دیگر مسیرهای سایدبار جابه‌جا نشده است.

تغییر در `ContractsPanel` اختیاری (`sectioned`) است؛ میزبان قدیمی آن در
`CostSupplyWorkspace` همچنان حالت ترکیبی قبلی را دارد. API، مدل داده، محاسبات،
گردش تصویب و مجوزهای موجود تغییر نکرده‌اند. درخواست جزئیات پیمان تنها زمانی
در UI پذیرفته می‌شود که هنوز همان پیمان انتخاب شده باشد؛ اطلاعات پیمان قبلی
برای پیمان تازه نمایش داده نمی‌شوند.

## پذیرش

- TypeScript و diff check موفق.
- ۱۰۰ تست متمرکز سرورِ پیمان، الحاقیه، تغییرات و صورت‌وضعیت موفق.
- تست مرورگر با دو پیمان موقت: تفکیک تمام مقصدها و نبود محتوای نامرتبط، حفظ
  پیمان دوم در رفت‌وبرگشت بخش‌ها و میز کارهای مستقل، ثابت‌ماندن انتخاب‌گر و
  بازگشت اسکرول محتوا به بالا بررسی شد.
- اختلاف scrollHeight/clientHeight قاب بیرونی در ۱۴۴۰×۹۰۰ و ۱۲۸۰×۸۰۰ صفر بود؛
  اسکرول فقط در محتوای بخش منتخب باقی می‌ماند.
- سناریوهای واقعی مرورگر u-contracts → u-pm برای الحاقیه و تغییر مقدار/کار جدید
  با دادهٔ موقت مستقل و پاک‌سازی پس از پایان مجدداً اجرا شدند. دادهٔ محیط کاربر
  ثبت یا تغییر داده نشد.
