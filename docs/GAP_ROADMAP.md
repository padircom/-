### SEC-1 — گزارش مرحله
- سیاست صریح خواندن/نوشتن برای تمام ۳۲ جدول عمومی در `server/dataAccess.js`؛ رد هویت ناشناخته/غیرفعال، مجوز جدول و محدودسازی پروژه در فهرست و رکورد. ثبت Excel از همان سیاست استفاده می‌کند و پیش از اولین نوشتن کل دسته را بررسی می‌کند.
- نوشتن خام جداول دارای گردش تأیید، مجوز پیکربندی سامانه می‌خواهد؛ مجوز تهیهٔ پیش‌نویس مجوز تغییر وضعیت خام نیست. مسیرهای اختصاصی CKM همچنان بسته‌اند.
- اصلاح fixtureهای cnt و hrm: بودجه با `u-ceo`، فعالیت با `u-planner` و دادهٔ خام کیفیت با `u-admin`؛ نقش‌های گردش‌کار تغییر نکردند. آزمون REST ورود itg برای پیش‌نمایش بدون نوشتن، ثبت مجاز، upsert و رد ثبت غیرمجاز اضافه شد.
- اعتبارسنجی: **۴۲۳۳/۴۲۳۳** آزمون موفق؛ `npx tsc --noEmit` بدون خطا؛ `npm run build` موفق.
- مرز امنیت: هویت همچنان از آداپتور موجود `x-user-id` و کاربران RBAC سامانه می‌آید، نه نشست رمزنگاری‌شده. در استقرار عمومی، درگاه احراز هویت باید هدر کاربر را جایگزین کند؛ این مرحله پیاده‌سازی ورود واقعی نیست.
- آزمون REST جدید با `PERSIST_DRIVER=json DATA_DIR=./server/rundata` اجرا می‌شود؛ harnessهای قدیمی مجموعهٔ آزمون، طبق طراحی قبلی، JSON موقت و ایزولهٔ خودشان را دارند.
- قرارداد OpenAPI برای هدر هویت و خطاهای 401/403 اصلاح شد؛ ثبت XER و کلاینت آن نیز کنترل مجوز گرفت تا مسیر موازیِ نوشتن برنامه باز نماند. رابطهٔ فعالیت بدون ستون پروژه، برای نقش دارای محدودهٔ پروژه بسته است.
- مرحلهٔ بعد در پایان SEC-1: LIVE-3؛ گزارش تکمیل آن در بخش بعد آمده است.

### LIVE-3 — گزارش مرحله (۲۰۲۶-۰۹-۲۷)
- `RiskClaimsWorkspace` بازنویسی شد: پروژهٔ واقعی از هر دو ورودی ماژول/قابلیت، هویت از AuthContext، فرم ثبت و ویرایش و نمایش وضعیت خالی/خطا/بدون مجوز. تعویض کاربر یا پروژه، دادهٔ قبلی را کنار می‌گذارد.
- API با کنترل هویت و مجوز پروژه‌ای، ۳ جدول اختصاصی، محاسبهٔ امتیاز ریسک و مهلت اعلان، قفل رکورد نهایی، کنترل `RowVersion`، جلوگیری از تصمیم هم‌زمان و ثبت لاگ ممیزی. فیلدهای جدید nullable و در مهاجرت **0036** هستند؛ پیش‌نویس‌های موجود باقی می‌مانند و مهلت نامعلوم به‌اشتباه معتبر فرض نمی‌شود.
- تغییر: ثبت پیش‌نویس، ارزیابی ۱۲ بُعد اثر، تصویب/رد با دلیل و توسط غیرتهیه‌کننده؛ هیچ عددی در برنامه/بودجه نوشته نمی‌شود. تولیدکنندگان پیش‌نویس مهندسی دیگر رکورد موجود را به پیش‌نویس برنمی‌گردانند.
- ادعا: مهلت طبق تاریخ رویداد و روزهای قراردادی؛ ثبت مرجع ابلاغ امروز (نه ارسال واقعی ایمیل/تحویل حقوقی)، قفل تاریخ/مهلت/بند پس از ابلاغ، امکان تکمیل مستندات؛ نهایی‌سازی توسط غیرتهیه‌کننده و فقط با ابلاغ به‌موقع، استحقاق، سببیت، مبنای مبلغ/مدت، مرجع مستندات، تاریخ داده و برنامهٔ مبنای جاریِ همان پروژه.
- CRUD عمومی برای ۳ جدول RCC بسته شد؛ اکنون ۲۹ جدول عمومی باقی است. مسیرهای عمومی قدیمیِ notices/guardian/suggests پاسخ 410 و راهنمای مسیر پروژه‌ای می‌دهند؛ دادهٔ نمونهٔ درون حافظه و job نمایشی حذف شد.
- از میراث `ForensicClaimsHub` مفاهیم ثبت ریسک، سببیت/استحقاق/کوانتوم و راهنمای تحلیل تأخیر به صفحهٔ فعال منتقل شد. **موتور کامل تحلیل تأخیر، مونت‌کارلو، قالب‌های خروجی و گردش ذخیره/مسئله/اختلاف/سرمایه‌گذاری در این مرحله تحویل نشده‌اند.** آن تب‌ها عدد یا ذخیرهٔ ساختگی ندارند؛ فایل میراثی دست‌نخورده و خارج از باندل باقی است.
- **آزمون‌ها: ۴۲۵۲/۴۲۵۲** (۱۹ آزمون جدید: ۸ واحد و ۱۱ REST، شامل راه‌اندازی مجدد، تفکیک وظیفه، جداسازی پروژه، نسخهٔ هم‌زمان و عدم تغییر مبنا). `npx tsc --noEmit` بدون خطا؛ `npm run build` موفق. آزمون دستی مرورگر و SQL Server انجام نشده است.
- سرور جدید آزمون فقط با `PERSIST_DRIVER=json DATA_DIR=./server/rundata` اجرا شد؛ پاک‌سازی فقط رکوردهای دارای پیشوند یکتای آزمون است، نه پوشهٔ داده. harnessهای قدیمی همچنان JSON موقت و ایزولهٔ خودشان را دارند.
- مرز استقرار: همان آداپتور هویت SEC-1؛ JSON برای یک فرایند API است، نه چند replica. تراکنش اتمیِ تغییر رکورد + ممیزی و قفل توزیع‌شده برای استقرار چندفرایندی در این مرحله اضافه نشده‌اند.
- پیشرفت: **42/85 = 49٪**؛ **P1: 16/16 = 100٪، P2: 3/3 = 100٪، P3: 9/9 = 100٪، P4: 2/8 = 25٪**. مرحلهٔ بعد **P4 / PAT-3** تولید نامه.


### LIVE-4 — گزارش مرحله (۲۰۲۶-۰۹-۲۷)
- پیش‌نمایش روی **۵۱۷۳** و API روی **۴۰۰۰** فعال است؛ API فقط با `PERSIST_DRIVER=json DATA_DIR=./server/rundata` اجرا شد. درخواست‌های مرورگر نسبی و از پراکسی Vite هستند؛ پاسخ وب و workspace از پراکسی با HTTP 200 بررسی شد.
- `MachineryWorkspace` بازنویسی شد: پروژه از ورودی ماژول، هویت از AuthContext، فرم و فهرست واقعی برای ناوگان، قرائت، سوخت، اجاره، تعمیرات، PM، دیسپچ و موجودی قطعات. تاریخ ثابت 2026-09-08، کد پروژهٔ ثابت و نمونه‌های ساختگی حذف شد. حالت خالی، خطای سرور، تعویض پروژه/کاربر و بازخوانی پس از ثبت مدیریت می‌شوند.
- API جدید `server/eqmWorkspaceApi.js`: `/api/eqp/:projectId/workspace`، ثبت/ویرایش `/rows/:table` و `/dispatch/:id/advance`. اسکیمای موجود کافی بود و مهاجرت جدید لازم نشد. اعتبارسنجی موتور `equipment.ts`، کنترل عدد/تاریخ، تعلق ماشین/اپراتور/فعالیت/حساب هزینه به پروژه، ساعت کار روز حداکثر ۲۴، ترتیب تاریخی ساعت‌شمار، نسخهٔ هم‌زمان و ممیزی اعمال شد.
- سه مجوز جدید: مشاهده، مدیریت و تصویب دیسپچ. **PMO** ثبت‌کننده؛ **مدیر پروژه/مدیر ارشد** تصویب‌کننده؛ کنترل هزینه فقط مشاهده دارد. نقش مدیر سامانه به‌طور ضمنی مجوز کسب‌وکار نمی‌گیرد. آزمون شمارش کاتالوگ RBAC به‌دلیل افزودن ۳ مجوز از ۱۸۶ به ۱۸۹ اصلاح شد.
- دیسپچ همیشه پیش‌نویس ساخته می‌شود؛ وضعیت/امضای جعلی از ورودی پذیرفته نمی‌شود. در ارسال/تصویب/اجرا، گواهی واقعی HRM، ایمنی، وضعیت ماشین، تعمیر بحرانی و PM دوباره کنترل می‌شود. تغییر پس از ارسال قفل است؛ تصویب‌کننده نمی‌تواند تهیه‌کننده باشد.
- مسیرهای موجود eqm/eqp نیز احراز هویت و مجوز پروژه گرفتند. ۹ جدول d9 از CRUD/ورود مستقیم Excel خارج شدند (اکنون **۲۰ جدول عمومی**). پیشبرد خام دیسپچ و نوشتن مستقیم پل مالی/برنامه از مسیر قدیمی با 410 بسته شد تا کنترل جدید دور زده نشود.
- صفحه به خلاصهٔ ناوگان، KPI هر ماشین و ناوگان، تابلوی دیسپچ، سررسید PM، پیشنهاد سفارش قطعات و دانلود احراز هویت‌شدهٔ CSV وصل است. بازهٔ کارکرد KPI به ۳۰ روز جاری محدود شد؛ `PlannedQty` دیگر تولید واقعی برای OEE محسوب نمی‌شود؛ امتیاز سلامت در نبود تاریخ بهره‌برداری در API نامعلوم است. سربرگ نمونهٔ گزارش کنار گذاشته شد و پروژهٔ واقعی استفاده می‌شود.
- محدودیت‌های صریح: TCO تعاملی، ثبت تولید واقعی و ظرفیت مرجع OEE، تراکنش ورود/خروج قطعه، ارسال خودکار خرید و فعال‌سازی مجدد پل‌های نوشتاری مالی/برنامه در این مرحله تحویل نشده‌اند. موجودی قطعه فعلاً مقدار ثبت‌شدهٔ ممیزی‌پذیر است، نه دفتر گردش انبار. PM کیلومتر/سیکل در نبود قرائت متناظر، مجوز دیسپچ نمی‌دهد. گزارش‌های قدیمی همچنان از موتور و قواعد محاسباتی موجود استفاده می‌کنند؛ بازطراحی کامل گزارش‌ها انجام نشده است.
