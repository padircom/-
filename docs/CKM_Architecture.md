# CKM — ماژول مدیریت ارتباطات و دانش
# سند معماری و پیاده‌سازی

نسخه ۱.۰ | 2026-09-08 | کد دامنه: `d11` | حالت: ارتقای درون‌برنامه‌ای

> **چهار اصل حاکم بر این ماژول**
> ۱) **اعلان قراردادی مهلت‌دار است** — نامه‌ای که تعهد قراردادی می‌سازد بدون مهلت پاسخ و بدون ارجاع به ادعا/تغییر/ریسک ثبت نمی‌شود.
> ۲) **مصوبه بدون مالک و موعد، مصوبه نیست** — یادداشت است.
> ۳) **دانش با استفاده مجدد سنجیده می‌شود، نه با ثبت شدن** — درسی که به کار نرود هزینه است نه دارایی.
> ۴) **ذی‌نفع با شکاف سطح تعامل سنجیده می‌شود، نه با فهرست اسامی.**

## ۱. تحلیل وضعیت موجود و مرزهای مالکیت

### ۱-۱. آنچه پیش از این ماژول وجود داشت

| دارایی موجود | مسیر | وضعیت پس از CKM |
|---|---|---|
| زیرفرآیند «مکاتبات» | `d1-p3` در ماژول مستندات | **دست‌نخورده می‌ماند**؛ اما گردش پاسخ و مهلت به CKM منتقل شد |
| زیرفرآیند «مدیریت دانش / درس‌آموخته» | `d1-p5` | همان؛ بانک دانش و ردیابی استفاده مجدد در CKM |
| زیرفرآیند «مدیریت ذی‌نفعان» | `d6-p3` در حاکمیت | حاکمیت مالک **ماتریس اختیار** می‌ماند؛ CKM مالک **سطح تعامل و برنامه ارتباطات** شد |
| `src/Communications.tsx` | فایل میراثی | یتیم، وابسته به `lucide-react`، تم روشن، در هیچ‌جا import نشده — **دست نخورد** |
| `ProjectKnowledgePanel.tsx` | کامپوننت موجود | دست‌نخورده |
| تقویم کاری پروژه | `planning.ts` → `addWorkingDays` | **مصرف مستقیم شد** — مهلت‌ها روز کاری‌اند نه روز تقویمی |

### ۱-۲. مرز مالکیت داده

| CKM مالک است (می‌نویسد) | CKM فقط می‌خواند |
|---|---|
| دفتر مکاتبات، کلاس نامه، مهلت پاسخ | فایل مدرک و نسخه‌ها ← `d1` |
| صورت‌جلسه، مصوبات، مالک و موعد | ادعا، تغییر، ریسک ← `d4` |
| ثبت ذی‌نفعان، سطح تعامل، ماتریس ارتباطات | عدم انطباق ← `d8` |
| بانک درس‌آموخته و شمارنده استفاده مجدد | ماتریس اختیار و سطوح تأیید ← `d6` |
| قواعد اعلان و سطوح تشدید | تقویم کاری ← `d2` |

چهار کلید به `DATA_OWNER` افزوده شد: `correspondence`, `meeting`, `stakeholder`, `lesson` → همگی `d11`.
