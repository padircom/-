# وضعیت اتصال منابع داده (سایدبار)

## دامنه و محدودیت واقعی API

این تغییر فقط کلاینت است؛ هیچ endpoint، پایگاه داده یا تنظیم اتصال بک‌اند تغییر
نکرده است. فهرست `dataSources` در `framework.ts` اکنون صرفاً نام/شناسه/آیکون/رنگ
و دستهٔ منبع را نگه می‌دارد؛ `connected` و `latency` نمونه حذف شده‌اند.

کلاینت از **مسیر موجود** `GET /api/integrations/status` می‌خواند. پاسخ فعلی سرور
شامل `id`, `configured`, `mode` است؛ health-check زنده، `connected`، `checkedAt`
یا زمان پاسخ واقعی ندارد. `configured: true` و آماده بودن import **به معنی
اتصال موفق نیست**. endpoint دیگر (`/api/integration/status`) نیز کاتالوگ قابلیت‌ها
است و جای health-check استفاده نمی‌شود.

پس در محیط فعلی:
- ورود فایل P6/MSP اتصال زنده محسوب نمی‌شود (خاکستری + «قطع» با توضیح).
- `configured: false` یعنی تنظیم اتصال انجام نشده (خاکستری + «قطع»).
- پیکربندی‌شده بدون بررسی سلامت، پاسخ نامعتبر/ناموجود و خطای شبکه: «نامشخص».
- Drilling DAS در پاسخ فعلی وجود ندارد و صریحاً «گزارش نشده» توضیح داده می‌شود.
- شناسهٔ `powerbi` از API به `pbi` موجود در UI نگاشت می‌شود.
- تعداد تأییدشده‌ها در هدر محاسبه می‌شود؛ هیچ «۷ از ۸» ثابت یا latency نمونه‌ای
  باقی نمی‌ماند. زمان دریافت HTTP هرگز به‌جای latency یک منبع نمایش داده نمی‌شود.

## قرارداد آمادگی برای سلامت زنده (هنوز توسط بک‌اند فعلی تولید نمی‌شود)

برای تأیید سبز، هر رکورد باید `connected: true` و `checkedAt` معتبر (ISO timestamp
زمان بررسی همان منبع، نه `meta.timestamp` پاسخ) داشته باشد. نتیجه باید حداکثر
۶۰ ثانیه قدیمی باشد؛ زمان‌های نامعتبر یا بیش از ۵ ثانیه جلوتر از ساعت کلاینت
پذیرفته نمی‌شوند. `latencyMs` عدد نامنفی اختیاری است و فقط همراه اتصال تأییدشده
نمایش داده می‌شود. `connected: false` قطعِ گزارش‌شده است (چراغ قرمز).

پیکربندی نشده، ورود فایل و پاسخ degraded بر ادعای اتصال اولویت دارند. تا زمانی
که بک‌اند نتیجهٔ health-check واقعی تولید نکند، صرف داشتن URL یا پاسخ موفق API
چراغ سبز نمی‌سازد. پیاده‌سازی پروب منابع خارجی بخشی از این تغییر نیست.

## چرخهٔ به‌روزرسانی و UX

- خواندن فقط از مسیر نسبی، با `x-user-id` نشست جاری و `cache: no-store`.
- دریافت اولیه و هر ۳۰ ثانیه در تب قابل‌مشاهده؛ timeout هشت‌ثانیه‌ای.
- بازگشت فوکوس/تب و آنلاین‌شدن، بازخوانی فوری انجام می‌دهد.
- آفلاین‌شدن، logout، تغییر کاربر، خطای HTTP یا شبکه، نتیجهٔ سبز قبلی را کنار
  می‌گذارد. پاسخ درخواست لغوشده یا کاربر قبلی اعمال نمی‌شود.
- در پس‌زمینه polling متوقف است؛ شواهد قدیمی منقضی و هنگام بازگشت بررسی می‌شوند.
- هنگام unmount، درخواست‌ها، تایمرها و listenerها آزاد می‌شوند.
- hover راهنمای علت را در `title` می‌دهد؛ انتخاب منبع، توضیح قابل‌مشاهده و
  `aria-describedby`/`role=status` را در سایدبار ارائه می‌کند. منطق انتخاب منبع
  عوض نشده است. پیام خام سرور (احتمالاً حاوی اطلاعات تنظیمات) نمایش داده نمی‌شود.

## آزمون‌ها

```sh
node --test tests/unit/dataSourceHealth.test.mjs
npx tsc --noEmit
npm run build
# با tooling مرورگر توضیح‌داده‌شده در tests/ui/README.md:
npx playwright test --config tests/ui/playwright.config.ts
```

- ۸ تست واحد برای قرارداد، تازگی شواهد، تشخیص ورودی نامعتبر، نگاشت شناسه و خطاها.
- ۱۰ تست مرورگری سلامت با پاسخ‌های کنترل‌شده؛ تأیید سبز صرفاً در fixture تستی
  شبیه‌سازی شده است، نه با اتصال به SAP/P6/Power BI واقعی.
- ۸ تست قبلی i18n/جای ثابت سایدبارها نیز اجرا می‌شوند.
- خود پیش‌نمایش با API واقعیِ موجود (بدون mock) بررسی شد: منابع پیکربندی‌نشده/
  ورود فایل سبز نیستند و DAS نامشخص است.
