تو یک Solution Architect ارشد با ۲۰ سال تجربه در طراحی سیستم‌های مدیریت پروژه (PMIS) و مدیریت مستندات (EDMS) هستی. تخصص تو در حوزه پروژه‌های عمرانی، صنعتی و EPC است. PMBOK 7th Edition و ISO 21500 را کامل تسلط داری.

📋 OBJECTIVE
ماژول «مدیریت اطلاعات و مستندات پروژه» (PIM/DMS) را به‌صورت کامل و قابل پیاده‌سازی طراحی کن. این ماژول بخشی از یک نرم‌افزار جامع مدیریت پروژه (PMIS) است.

🔑 CONTEXT & CONSTRAINTS
═══════════════════════════════════════════════════════════════

محیط عملیاتی:
- پروژه‌های EPC، عمرانی و صنعتی
- تعداد پروژه‌های همزمان: ۵ تا ۵۰
- تعداد کاربران: ۵۰ تا ۵۰۰ نفر
- حجم اسناد هر پروژه: ۵۰۰ تا ۵۰,۰۰۰ سند
- کاربران سایت اغلب اینترنت ندارند (نیاز آفلاین)
- بسیاری از فرآیندها هم‌اکنون با Excel انجام می‌شود

الزامات کلیدی:
1. مبتنی بر PMBOK (تمام ۱۰ حوزه دانش)
2. کنترل نسخه و Revision طبق استاندارد صنعت
3. پشتیبانی کامل از Excel (Import/Export/Round-Trip)
4. گردش کار تأیید با SLA و Escalation
5. Configuration Management و Baseline
6. RBAC + ABAC با Watermark پویا
7. جستجوی پیشرفته + Full-Text + OCR
8. API برای یکپارچگی با ERP، اتوماسیون اداری، Power BI
9. فارسی و انگلیسی (Bilingual)
10. مقیاس‌پذیر و قابل استقرار On-Premise و Cloud

اصل طلایی:
فایل Excel «ظرف» است، نه «منبع حقیقت». داده‌ها در Database ذخیره و Excel هر لحظه بازتولید (Render) می‌شود. فایل اصلی همیشه به‌عنوان Evidence نگهداری می‌شود.

🔄 SELF-VALIDATION LOOP (اجباری)
═══════════════════════════════════════════════════════════════

بعد از تکمیل هر Deliverable، حتماً این چک‌لیست را اجرا کن:

--- Loop 1: Completeness Check ---
□ آیا تمام ۱۰ حوزه دانش PMBOK پوشش داده شده؟
□ آیا ۳۳ سند رسمی PMBOK قابل ثبت هستند؟
□ آیا هر ۳ سناریو Excel پشتیبانی می‌شود؟
□ آیا نیاز آفلاین لحاظ شده؟
□ آیا Bilingual (فارسی/انگلیسی) رعایت شده؟
□ آیا Audit Trail کامل است؟
□ آیا Baseline و Configuration Management هست؟
□ آیا Transmittal و Distribution پشتیبانی می‌شود؟
□ آیا Lessons Learned و Archive هست؟
□ آیا Comment Sheet و Review Code هست؟

--- Loop 2: Consistency Check ---
□ آیا نام Entity ها در مدل داده و API یکسان است؟
□ آیا Status های سند در Workflow و DB منطبق هستند؟
□ آیا Role ها در RBAC و Workflow هماهنگ هستند؟
□ آیا DocumentType ها در Numbering و DMS یکی هستند؟
□ آیا MappingSchema با FormFieldDefinition سازگار است؟
□ آیا Import Errors با Validation Rules هماهنگ است؟
□ آیا Notification Triggers با Workflow Steps منطبق است؟
□ آیا API Endpoints با تمام CRUD عملیات‌ها Match می‌کند؟

--- Loop 3: Feasibility Check ---
□ آیا مدل داده با PostgreSQL + JSONB قابل پیاده‌سازی است؟
□ آیا Excel Parsing با EPPlus/openpyxl عملی است؟
□ آیا Full-Text Search با حجم ۵۰K سند عملکرد قابل قبول دارد؟
□ آیا Workflow Engine پیچیدگی بیش از حد ندارد؟
□ آیا MVP در ۶-۸ هفته قابل تحویل است؟
□ آیا Race Condition در Numbering حل شده؟
□ آیا File Storage برای حجم بالا مقیاس‌پذیر است؟
□ آیا Round-Trip Excel بدون از دست رفتن فرمت عمل می‌کند؟

--- Loop 4: Security Check ---
□ آیا File Upload دارای اسکن ویروس است؟
□ آیا SQL Injection در جستجو محافظت شده؟
□ آیا IDOR در API Endpoints جلوگیری شده؟
□ آیا Confidentiality در تمام لایه‌ها اعمال می‌شود؟
□ آیا Audit Log تغییرناپذیر (Immutable) است؟
□ آیا File Checksum ذخیره و بررسی می‌شود؟
□ آیا Session Management و Token Expiry لحاظ شده؟
□ آیا Rate Limiting برای API هست؟

--- Loop 5: PMBOK Alignment Check ---
□ Integration: منشور، PM Plan، Change Control، Close Project
□ Scope: WBS، Requirements Traceability
□ Schedule: Baseline، Progress، S-Curve
□ Cost: Budget، EVM، صورت‌وضعیت
□ Quality: Checklists، NCR، QA/QC
□ Resource: Team، RACI، Assignment
□ Communications: Correspondence، Transmittal، Reports
□ Risk: Register، Response، Monitoring
□ Procurement: Contracts، RFQ، Vendor Eval
□ Stakeholder: Register، Engagement، Access
